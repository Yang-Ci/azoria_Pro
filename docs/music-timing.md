# 音乐播放时间与歌词同步

参考 [smallmb/Dz](https://github.com/smallmb/Dz/tree/6452c41aa6649952144293001151c2399658963c)
的媒体时间推进和歌词显示方式，采用以下处理。参考版本为
`6452c41aa6649952144293001151c2399658963c`，参考项目采用 MIT 许可证。

- 原生媒体组件提供实际播放位置和采样时间。Windows 仍通过 SMTC 读取；原有
  `LastUpdatedTime` 补偿继续使用。歌词接口只提供歌词内容和时间戳，不提供电脑播放器的实时进度。
- 主进程和桌面界面接收样本时补偿采样至接收的延迟，之后通过 `performance.now()`
  推进，避免两次采样之间系统时间调整造成进度跳变。跨进程仍传递墙上时钟时间戳，
  发送时将位置和采样时间一起更新。新系统样本负责校正暂停、拖动、切歌和倍速。
- 播放状态轮询不等待歌词或封面。相同歌曲的后台请求合并，加载失败后等待 30 秒重试，
  旧歌曲的歌词结果只能更新其缓存，不能覆盖另一首正在显示的歌曲。
- 桌面和 Touch 的歌词选择提前 350 毫秒，参考 Dz 的 `lyric_position()`。
  此提前量仅用于选择显示的歌词；播放进度、拖动目标和手动校准位置保持实际值。
- 播放器未提供位置时仍标记为估算。手动定位后按单调时钟继续推进；
  QQ 音乐没有提供进度的情况下，无法通过歌词 API 自动恢复真实位置。

## 验证

`desktop/tests/music.test.cjs` 使用可控时钟和延迟请求验证采样延迟、系统时间跳变、
暂停、拖动、倍速、手动校准、歌词和封面请求阻塞、切歌后的过期返回，以及请求失败重试。
模拟测试不能替代各播放器版本的实机同步验收。
